# 開發者日誌 V2026-05-27-01

更新日期：2026-05-27

## 來源

本次依據 `prompt` 的產品策略檢核方向調整。該檔案要求用「願意投資 3000 萬新台幣」的標準檢視 prototype，重點不是稱讚 UI，而是補強價值主張、交易設計、信任機制、留存、成長與商業模式。

## 本次判斷

目前產品最有價值的入口仍是「哩程/點數缺口試算」，但若只停在計算工具，使用者得到答案後就會離開。下一步應該把試算結果轉成明確決策：官方補哩、繼續刷卡累積、或在缺口夠大時進入媒合資訊。

媒合不是越早越好。若缺口小、已達標、資料不足，直接推媒合會增加教育成本與信任成本。現階段不應加入第三方金流或履約保證，應先把風控資料、身份驗證、可轉讓規則與評價機制補起來。

## 已落地改善

- 版本更新為 V10。
- 首屏價值主張改為「先算缺口，再選補法」，明確定義產品不是單純信用卡比較，而是補點決策工具。
- 新增「信任與下一步」區塊，說明平台目前只做試算、官方連結、缺口保存與媒合資訊，不處理第三方金流、代管或履約保證。
- 依試算結果動態更新信任提示：
  - CUBE 小樹點：先確認官方權益，不進入固定哩程媒合。
  - 資料不足：不建議媒合。
  - 已達標：先查票與確認兌換條件。
  - 小缺口：官方補哩或自然消費優先。
  - 中大型缺口：才把媒合作為值得比較的下一步。
- 缺口追蹤資料新增 `decision` 與 `trustNote` 欄位，為後續 App 版提醒、回訪與風控策略保留資料。

## 尚未落地但應列入下一輪

- 即時報價或合理價格區間，否則媒合頁仍缺少「我現在該不該換」的立即回報。
- 身份驗證、評價、黑名單、履約紀錄與可轉讓規則檢核，這些是媒合成立前的基本門檻。
- 點數資產儀表板與到期提醒，解決低頻產品留存問題。
- 分享誘因與首批種子用戶設計，例如常出國兌換哩程的人、旅遊社群、信用卡社群與里程玩家。
- B2B2C 合作方向，例如旅遊顧問、旅行社、信用卡內容站或航空哩程顧問服務。

## 下一步建議

下一版不應先做更多卡片或更多頁籤，而應補「報價可信度」與「交易安全感」。若使用者看不到合理價格、風險邊界與對方可信度，媒合功能即使做出來也很難產生第一筆成功交易。
