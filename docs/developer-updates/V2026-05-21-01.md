## 產品定位

目前產品是一套以 Vue 3 + TypeScript + Vite 建置的「積分兌換 App」，主要涵蓋：

- 使用者選擇與登入
- 積分查詢
- 禮物兌換申請
- 任務完成申請
- 積分與兌換歷史查詢
- 管理員後台審核與維護

產品目前偏向單機前端示範版，主要資料保存在瀏覽器 `localStorage`，尚未接入後端 API、資料庫或正式權限系統。

## 目前頁面與流程

### 1. 首頁

首頁根據是否已有 `currentUser` 分成兩種狀態：

- 未登入：引導至使用者選擇頁
- 已登入：顯示使用者資訊、當前積分、熱門禮物、功能入口

功能入口包含：

- 禮物兌換
- 任務中心
- 歷史記錄
- 管理後台入口

### 2. 使用者登入流程

目前沒有帳密登入，採用「從使用者列表直接選擇登入」：

- 使用者於 `/users` 頁面選擇既有使用者
- 系統將該使用者寫入 `currentUser`
- 之後返回首頁顯示對應個人資訊

此流程代表目前產品仍屬原型或展示階段，尚未具備正式身份驗證能力。

### 3. 禮物兌換流程

使用者可在 `/gifts`：

- 瀏覽禮物列表
- 查看禮物圖片、描述、所需積分、庫存
- 發起兌換申請

兌換申請建立時：

- 只建立 `pending` 狀態的兌換單
- 不會立即扣點
- 待管理員審核後，若核准才扣除積分並減少庫存

### 4. 任務中心流程

使用者可在 `/tasks`：

- 查看任務名稱、描述、可獲得積分
- 提交任務完成申請
- 查詢自己任務申請的審核狀態

任務完成申請建立時：

- 先建立 `pending` 狀態的任務完成紀錄
- 管理員核准後才實際加點

### 5. 歷史查詢

`/history` 目前分成兩個分頁：

- 積分變動記錄
- 兌換記錄

其中兌換記錄頁面也整合了任務完成紀錄，讓使用者可同時查看：

- 任務申請審核狀態
- 禮物兌換審核狀態
- 已核准項目造成的積分變動

## 管理後台現況

### 1. 管理員登入

管理後台入口為 `/admin`。

目前實作：

- 單一固定密碼 `admin123`
- 驗證通過後設定 `isAdmin = true`
- Router 透過 `meta.requiresAdmin` 控制後台頁面存取

此設計代表目前僅為前端示範級權限控制，不適用正式環境。

### 2. 使用者管理

`/admin/users` 已支援：

- 新增使用者
- 編輯使用者基本資料
- 刪除使用者
- 手動調整積分

積分調整會同步寫入 `pointHistories`，保留積分異動原因與時間。

### 3. 禮物管理

`/admin/gifts` 已支援：

- 新增禮物
- 編輯禮物
- 刪除禮物
- 上傳圖片

圖片目前以 Base64 Data URL 或既有圖片 URL 形式存於前端資料中，未上傳到外部檔案服務。

### 4. 兌換審核

`/admin/exchanges` 已支援：

- 查看待審核兌換申請
- 核准兌換
- 拒絕兌換
- 查詢已處理兌換歷史

核准時的系統行為：

- 兌換單狀態改為 `approved`
- 寫入處理時間
- 禮物庫存減 1
- 使用者積分扣除對應點數
- 積分異動寫入歷史

### 5. 任務管理與審核

`/admin/tasks` 已支援：

- 新增任務
- 編輯任務
- 刪除任務
- 審核待處理任務完成申請

核准任務完成時：

- 任務完成紀錄改為 `approved`
- 寫入審核時間
- 使用者增加任務獎勵積分
- 積分異動寫入歷史

## 狀態管理與資料模型

目前核心狀態集中在 `src/stores/appStore.ts`，資料包含：

- `users`
- `gifts`
- `pointHistories`
- `exchanges`
- `tasks`
- `taskCompletions`
- `currentUser`
- `isAdmin`

並提供衍生資料：

- `pendingExchanges`
- `pendingTaskCompletions`
- `userExchanges(userId)`
- `userTaskCompletions(userId)`

資料模型型別集中在 `src/types/index.ts`，目前結構清楚，適合後續抽換成 API model 或 DTO。

## 目前資料儲存策略

目前資料透過 `localStorage` 的 `points-exchange-data` 儲存，特性如下：

- 首次進入系統時會載入預設假資料
- 所有新增、編輯、審核操作都直接覆寫本機儲存
- 沒有多人同步能力
- 沒有資料版本控制
- 沒有後端驗證與操作稽核

這表示目前產品比較接近「前端功能原型」與「互動流程驗證版」。

## 已知限制與開發風險

### 1. 權限與安全性不足

- 管理員密碼硬編碼於前端
- 沒有正式登入機制
- 沒有 token / session / API 驗證

### 2. 資料層仍為前端假資料

- 所有資料均在瀏覽器端
- 清除瀏覽器資料後內容可能消失
- 不支援跨裝置或多人同時操作

### 3. 業務規則仍偏簡化

- 兌換流程沒有物流、領取、取消等狀態
- 任務完成沒有證明附件、審核備註、重複規則等欄位
- 使用者管理缺少停權、角色、群組等管理能力

### 4. 可維運性仍可再提升

- 目前核心商業邏輯集中在單一 store，後續功能擴大時需要拆模組
- 尚未看到測試、API 抽象層、錯誤追蹤機制
